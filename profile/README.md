<p>混用确实省钱：一台机器、一套环境、几条线轮着上，机器费减半，布线时间也省一半。问题是省下来的钱会不会以另一种方式花出去。这篇用一个四周的对照，专门测混用的代价——把账号牵连率、首登成功率、异常恢复耗时和操作人力四项放在一起比，最后给一条能落地的分界线。</p>
<h2>一、要回答的问题</h2>
<p>不是「住宅 IP 好不好」，而是「混用到什么程度开始亏」。所以三个组按混用程度排，而不是按线路类型排。线路全部用原生家宽，把这层变量先抹平，剩下的差异才归因得清。</p>
<h3>为什么把线路统一</h3>
<p>如果一组用机房线、一组用家宽线，测出来的是线路差异，不是混用差异。研究混用就必须让线路相同，只改隔离程度。</p>
<p>还有一点要提前说清：这套结论只对同等规模适用。三五个号的经验直接套到五十个号上，往往因为出口密度和人力结构变化而失效，规模翻倍后建议按比例再验一次。</p>

<h2>二、实验设计</h2>
<h3>账号与任务</h3>
<p>每组三个号，注册时间相差不超过一周，任务内容统一为每天二十轮中等长度对话，时段固定在当地上午。四个周的观察期内不作任何配置变更，出现异常只记录不处理，避免人为干预污染数据。</p>
<h3>一台机器一套环境到底怎么理解</h3>
<p>这句话容易被误解成「一台机器只放一个号」。更准确的理解是：一台机器可以放多个号，但每个号必须有独立的配置文件，且配置文件之间不共享任何可识别字段。丙组做的是物理隔离，属于最保守的做法，成本也最高。</p>
<h3>记录方式</h3>
<p>每行一条记录：时间、账号、出口地址、状态、是否牵连其他账号。最后一项是这次的实验重点——某个号出问题时，同组其他号是否在同一小时内也出现异常。是则记为一次牵连。</p>

<h2>三、四项观测指标</h2>
<h3>账号牵连率</h3>
<p>牵连次数除以异常次数。这个指标最能反映混用的真实代价：一个号出问题，牵连几个号，损失就翻几倍。</p>
<h3>首登成功率</h3>
<p>新号首次登录一次通过的占比。混用环境下这个数字通常更低，因为新号进入的是一个已有其他账号痕迹的环境。</p>
<h3>异常恢复耗时与操作人力</h3>
<p>恢复耗时指从发现异常到恢复正常使用的时间。操作人力指四周内花在配置、切换、排查上的总分钟数。前者反映损失，后者反映成本，两者一起看才完整。</p>

<h3>读出来的三件事，以及性价比拐点</h3>
<p>牵连率从六成降到不足两成，只做了配置文件隔离这一件事，说明「串」主要发生在环境层。首登通过率的差距更直接：新号进混合环境，等于背着别人的痕迹起步。人力那栏有意思，丙组反而比乙组高，因为三台机器要维护三份系统环境，物理隔离并不是零成本。</p>
<p>一台机器加多份配置，兼顾了隔离与成本。除非账号价值特别高，或者需要跨地区长期驻留，否则没必要上到丙组。这条结论对预算有限的团队最有用。</p>
<h2>五、结论与边界</h2>
<h3>混用的红线在哪</h3>
<p>三条：不共用出口、不共用配置文件、不在同一分钟内操作同组多个号。三条守住，混用的代价基本可控；破一条，牵连率立刻上升。</p>
<h3>这套结论不适用的情况</h3>
<p>账号价值极高（比如绑定了付费订阅且有历史数据）、需要固定在特定城市、或者团队多人远程协作时，丙组的物理隔离更稳妥。判断标准是「一次异常造成的损失是否超过三个月的机器差价」。</p>
<h3>什么时候该重测</h3>
<p>换城市、换服务商、账号量翻倍、平台侧提示变化，四种情况任一发生，建议重跑一个两周的短周期。旧读数一般三个月内有效，超过就别再拿它做决策。</p>
<h2>常见问答</h2>
<h3>三个号用一台机器，只做配置文件隔离够吗？</h3>
<p>答：实验里乙组就是这么做的，牵连率降到两成以下。如果号的价值不高，这个程度够用；价值高的号建议单独一台。</p>
<h3>牵连率怎么算才不算冤枉？</h3>
<p>答：同一小时内同组其他号出现异常才算牵连，隔了几小时的不算。口径提前定死，事后不要改。</p>
<h3>为什么丙组人力反而更高？</h3>
<p>答：三台机器要维护三份系统更新、三份网络配置，日常巡检工作量翻倍。物理隔离买到的是确定性，不是省力。</p>
<h3>实验期间出现异常真的不处理吗？</h3>
<p>答：记录期内不处理，是为了让数据干净。如果异常持续超过两天，应中止该组并记为失败，继续跑下去没有意义。</p>
<h2>合规提示</h2>
<p>实验应使用自有或明确授权的账号，不得以测试为名进行批量注册或探测平台规则边界。</p>
<p>实验记录包含账号与地址信息，应按内部数据规范保存，结束后及时归档或清理。</p>
